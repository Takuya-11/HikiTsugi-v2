## 1. プロジェクト概要

**プロダクト名**: HikiTsugi v2  
**コンセプト**: 引き継ぐ人は簡単に。引き継がれる人には分かりやすく。  
**目的**: IT運用業務の担当者交代時に発生する「引き継ぎ書の書き方がわからない」「フォーマットがバラバラ」「手順が抜ける」という課題を、フォーム入力と構造化テンプレートで解決する。

---

## 2. ユーザー定義

### 2.1 作成者
- **定義**: 引き継ぎ書を作成・管理する担当者
- **認証**: ログイン必須
- **権限**: 自分が作成した引き継ぎ書の作成・編集・削除・共有管理
- **想定**: IT運用業務の引き継ぎ元担当者

### 2.2 閲覧者
- **定義**: 共有URLを通じて引き継ぎ書を閲覧する担当者
- **認証**: ログイン不要（URLを知っていればアクセス可能）
- **権限**: 共有中の引き継ぎ書の閲覧のみ（編集・削除不可）
- **想定**: IT運用業務の引き継ぎ先担当者、上長、レビュアー

### 3.2 ログイン画面（`/login`）
- メールアドレス・パスワード入力
- ログインボタン
- アカウント登録ページへのリンク
- エラーメッセージ表示領域

### 3.3 アカウント登録画面（`/register`）
- メールアドレス・パスワード・パスワード確認入力
- 登録ボタン
- ログインページへのリンク

### 3.4 ダッシュボード（`/dashboard`）
- 自分が作成した引き継ぎ書の一覧
- 一覧情報: タイトル・作成日・更新日・共有状態
- 新規作成ボタン
- 各ドキュメントへのアクション: 編集・プレビュー・共有管理・削除

### 3.5 新規作成画面 / 編集画面
- 5セクション構成のフォーム
  1. 基本情報（業務名・概要・担当者・カテゴリ・頻度・作成日）
  2. システム・環境情報（システム名・環境・対象機器・OS・ツール・接続情報・参考URL）
  3. 作業手順（複数）: 手順名・作業内容・実施タイミング・事前確認・操作コマンド・確認方法・中止条件・ロールバック・事後確認・注意点
     - **【Phase 4確定】並び替え: 上下移動ボタン（上へ・下へ）で順序変更。将来のDnD実装に備えorderフィールドを保持する**
  4. 障害対応（複数）: 障害内容・確認事項・一次対応・復旧確認・エスカレーション先・エスカレーション条件・注意点
  5. 注意事項・参考資料: 注意事項・禁止事項・補足・参考資料リスト
- セクションナビゲーション（サイドバー or タブ）
- **【Phase 4確定】自動保存インジケーター（3状態）**:
  - `保存中...` — 最後の入力から2秒以内（debounce中またはサーバー送信中）
  - `保存済` — サーバー保存完了
  - `保存失敗` — ネットワークエラー等（ローカルバックアップに保存済みを明示）
- バリデーション + エラー表示

### 3.6 プレビュー画面（`/documents/:id/preview`）
- 編集中の引き継ぎ書の印刷用プレビュー
- PDF保存・印刷ボタン
- 編集に戻るボタン

### 3.7 共有管理画面（`/documents/:id/share`）
- 現在の共有状態表示
- 共有URL生成ボタン（未発行時）
- 共有URL表示 + コピーボタン（発行済み時）
- 共有停止ボタン（共有中の時）
- **【Phase 4確定】有効期限設定UIはMVPに含まない。手動停止のみ実装。DBは将来の期限設定に対応できる設計にする。**

### 3.8 閲覧画面（`/view/:token`）
- 有効な共有URLからアクセスした閲覧者向け
- ログイン不要
- 読み取り専用表示（編集UIなし）
- PDF保存・印刷ボタン
- プロジェクト説明 + 新規登録への導線（下部フッター）

### 3.9 アクセスエラー画面（`/error`）
- 無効・停止済みの共有URLにアクセスした時
- エラー種別に応じたメッセージ:
  - `共有が停止されました`
  - `このURLは有効ではありません`
  - （将来）`共有期限が切れました`

## 4. 共有トークンの状態管理

| 状態 | 説明 | MVPでの扱い |
|---|---|---|
| 未発行 | 共有URLを発行していない | ○ 実装 |
| 共有中 | 有効な共有URL存在、閲覧可能 | ○ 実装 |
| 停止済み | 手動停止済み、閲覧不可 | ○ 実装 |
| 期限切れ | 有効期限を過ぎた（将来機能） | △ DB設計のみ対応、UI・ロジックはv1.0以降 |

**停止済みトークンの再発行**: 停止後に新しいトークンを発行可能。旧トークンは無効のまま。

## 5. 自動保存の仕様（Phase 4確定）

```
入力イベント
    ↓
debounce 2秒
    ↓
サーバーへ送信（PATCH /api/documents/:id）
    ↓ 成功             ↓ 失敗
「保存済」表示      ローカルバックアップに書き込み
                    「保存失敗」表示（ローカル保存済を明示）
```

### 競合検知
- 各ドキュメントに `updated_at` タイムスタンプ（またはversionカウンタ）を持つ
- 送信時に最後に読み込んだ `updated_at` を一緒に送信
- サーバー側で差異を検知 → `409 Conflict` を返す
- クライアントは競合ダイアログを表示（「あなたの変更」vs「サーバーの変更」の差分表示）

## 6. ナビゲーション設計

```
未ログイン
  → /login
  → /register
  → /view/:token（閲覧のみ）

ログイン後
  → /dashboard（起点）
      → /documents/new（新規作成）
      → /documents/:id/edit（編集）
          → /documents/:id/preview（プレビュー）
          → /documents/:id/share（共有管理）
      → ログアウト → /login
```
